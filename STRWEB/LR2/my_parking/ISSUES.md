## ISS-001. Будущий промокод отображается как активный

- Связанное требование: FR-22.
- Компонент: `parking.views.promo_list`.
- Предусловие: существует промокод с `is_active=True`, `valid_from > today`, `valid_until > today`.

Шаги:

1. Создать промокод `VERIFY-FUTURE` со сроком действия, начинающимся через 30 дней.
2. Открыть `/promocodes/`.
3. Проверить раздел активных промокодов.

Ожидаемый результат: код не находится среди активных, поскольку срок ещё не начался.

Фактический результат: `VERIFY-FUTURE` отображается среди активных.

Причина по коду: запрос проверяет только `is_active=True` и `valid_until__gte=today`, но не проверяет `valid_from__lte=today`.

## ISS-002. Истёкший промокод отображается в каталоге услуг

- Связанное требование: FR-22.
- Компонент: `parking.views.services_catalog`.
- Предусловие: существует промокод с `is_active=True` и `valid_until < today`.

Шаги:

1. Создать промокод `VERIFY-EXPIRED`, истёкший 30 дней назад, но оставить `is_active=True`.
2. Открыть `/services/`.
3. Проверить блок промокодов.

Ожидаемый результат: истёкший код отсутствует.

Фактический результат: `VERIFY-EXPIRED` отображается в каталоге.

Причина по коду: каталог выбирает только по `is_active=True`, не учитывая `valid_from` и `valid_until`.

## ISS-003. Некорректное поле сортировки вызывает HTTP 500

- Связанные требования: BR-03, UR-07, FR-25, NFR-02.
- Компонент: `parking.views.admin_panel`.
- Предусловие: пользователь вошёл как администратор.

Шаги:

1. Открыть `/admin-panel/?user_sort=not_a_field`.
2. Зафиксировать HTTP-статус.

Ожидаемый результат: параметр отклонён либо заменён допустимым значением; панель остаётся доступной.

Фактический результат: HTTP 500, исключение `django.core.exceptions.FieldError`.

Причина по коду: значение GET-параметра без белого списка передаётся в `clients_list.order_by(params['user_sort'])`.

Дополнительный риск: пользователь управляет выражением сортировки ORM. Даже без прямой SQL-инъекции это позволяет стабильно нарушать доступность страницы.

## ISS-004. Некорректная дата фильтра вызывает HTTP 500

- Связанные требования: BR-03, UR-07, FR-25, NFR-02.
- Компонент: `parking.views.admin_panel`.
- Предусловие: пользователь вошёл как администратор.

Шаги:

1. Открыть `/admin-panel/?start_date=bad-date`.
2. Зафиксировать HTTP-статус.

Ожидаемый результат: отображено сообщение о неверном формате либо использована дата по умолчанию.

Фактический результат: HTTP 500, исключение `django.core.exceptions.ValidationError`.

Причина по коду: строковые GET-параметры сразу передаются в фильтр `date__range` без предварительной валидации.

## ISS-005. Секреты хранятся в исходном коде, список хостов не ограничен

- Связанное требование: NFR-05.
- Компоненты: `core.settings`, `parking.views.home`, `docker-compose.yml`.

Шаги:

1. Открыть `core/settings.py`.
2. Найти `SECRET_KEY` и `ALLOWED_HOSTS`.
3. Открыть `parking/views.py` и найти `api_key` в функции `home`.
4. Сравнить с переменными окружения Docker Compose.

Ожидаемый результат: секреты читаются из окружения; production-хосты перечислены явно.

Фактический результат:

- Django `SECRET_KEY` записан непосредственно в `settings.py`;
- ключ OpenWeather записан непосредственно в `views.py`;
- `ALLOWED_HOSTS` содержит `'*'`;
- Docker Compose задаёт `SECRET_KEY`, но настройки не читают эту переменную.

Риск: утечка ключей при публикации репозитория и ослабление проверки заголовка `Host`.
